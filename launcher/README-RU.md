# SA:COOP Launcher 1.1.1

Автономный Windows x64 лаунчер: обновление SA:COOP и установка сборки с модами из собственной GTA игрока.

## Новая установка игры с модами

1. Распакуйте `SA-COOP-Launcher-win-x64.zip` и запустите EXE.
2. Откройте **«Установить игру»**.
3. Выберите папку со своей полной GTA San Andreas **1.0 US**. Несовместимый EXE и неполная игра отклоняются до скачивания.
4. Выберите новую папку назначения. Кнопка «Выбрать» добавляет имя `GTA San Andreas - SA COOP` внутри выбранной родительской папки; путь можно изменить вручную.
5. Закройте GTA и сервер, нажмите **«Установить игру с SA:COOP»** и дождитесь завершения.
6. Нажмите **«Играть»**. Ник и подключение к другу задаются через F9 в GTA.

Базовую GTA лаунчер берёт из собственной установленной копии игрока. Полная игра на GitHub не размещается.
Он копирует базовые игровые папки и runtime DLL, затем скачивает пакет модов этой сборки и последнюю стабильную SA:COOP.
Моды, установленные в другой исходной копии, поверх нашего пакета не переносятся.

Пакет содержит текущие ModLoader-моды, CLEO, ASI-загрузчики, SilentPatch, исправления для 60 FPS и их настройки.
При новой установке лаунчер автоматически включает 4GB-патч (LAA) в скопированном `gta_sa.exe` и пересчитывает PE-контрольную сумму.
Если LAA уже включён, EXE не переписывается. Исходный файл остаётся на месте. Это не преобразование другой версии GTA в 1.0 US.
Обычное обновление SA:COOP существующий `gta_sa.exe` не меняет.
Имеющиеся авторские readme и лицензии включены. Пакет: примерно 952 МБ скачивания и 2 ГБ после распаковки.
Нужно место для копии GTA, модов и временных файлов; лаунчер проверяет свободное место на обоих дисках.

Исходная GTA остаётся на месте. Сейвы, `gta_sa.set`, адреса, пароли, серверные профили, снимки мира,
логи, старые архивы и исходники проекта в новую сборку не копируются. Новая `coop.ini` содержит нейтральные значения.
Сохранения GTA в «Документах» остаются общими для установленных копий игры; установщик их не трогает.

Папка назначения должна быть новой или пустой. Сначала всё собирается в отдельной временной папке рядом с ней.
Только после успешной проверки папка переименовывается в выбранную. При ошибке или отмене удаляются только файлы текущей незавершённой установки.
После аварийного завершения Windows может остаться папка `.sa-coop-install-*` рядом с выбранным местом: её можно удалить вручную при закрытом лаунчере.
Исходная GTA от такого сбоя не меняется.

## Обновление установленной SA:COOP

1. Распакуйте `SA-COOP-Launcher-win-x64.zip`. Можно положить `SA-COOP Launcher.exe`
   рядом с `gta_sa.exe` либо держать отдельно.
2. Запустите лаунчер. Если игра не найдена, выберите её папку в настройках.
3. Нажмите «Проверить обновления». Если вышла новая сборка, кнопка внизу станет «Обновить».
4. Закройте GTA и `coop-server.exe` перед обновлением. Лаунчер сам процессы не завершает.
5. После установки нажмите «Играть». Сессия по-прежнему создаётся/подключается через F9 в игре.

Отдельный .NET или Git игрокам не нужен: выпуск содержит автономный Windows x64 EXE.
Исходный репозиторий обновлений: `MortysCode/GTASA-COOP`.
Источник закреплён в программе. Его нельзя изменить через интерфейс, настройки JSON или параметры запуска.
Старое поле Repository из настроек версии 1.0.0 игнорируется и больше не сохраняется.
Открытые исходники технически можно пересобрать с другим адресом, но это будет изменённая сборка.
Поддерживаются публичные репозитории, аккаунт GitHub для скачивания не нужен.
Пустой репозиторий, отсутствие релиза и недоступность сети не мешают запуску установленной игры.

Вкладка «Обновления» позволяет также выбрать наш локальный ZIP с `SHA256SUMS.txt`.
Используйте архивы, происхождение которых вам известно: контрольная сумма внутри локального
архива выявляет повреждение, но сама по себе не удостоверяет издателя.

## Что сохраняет обновлятор

Обновляются только `coop.asi`, `coop/coop-server.exe` и `coop/coop.pdb`.
`coop.ini`, серверные настройки, профили, мир, GTA, SilentPatch и другие плагины не заменяются.
До замены проверяются SHA-256 архива и каждого файла. Не извлекаются произвольные пути ZIP.
Пути с выходом за папку и повторные записи отклоняются; установка через junction/symlink не поддерживается.

Резервные копии: `coop/backups/launcher-ДАТА-ИДЕНТИФИКАТОР/original/`.
Перед записью сохраняется журнал; сбой приводит к восстановлению исходных файлов.
Если процесс/питание оборвались, при следующем открытии лаунчер восстанавливает незавершённую
операцию до запуска игры. Повреждённая резервная копия блокирует восстановление и запуск через
лаунчер, чтобы не продолжать с неполной сборкой. Не запускайте GTA напрямую при незавершённом обновлении.

Для ручного отката закройте GTA и сервер, верните три файла из `original` в соответствующие
места папки игры. Оба участника должны использовать совместимые версии мода.

Настройки и журнал лаунчера: `%LOCALAPPDATA%/SA-COOP Launcher/`.
Файлы обновлений скачиваются в подпапку `work` и удаляются после завершения операции.
Лаунчер не хранит GitHub-токены и не отправляет сохранения на GitHub.

## Издателю: релиз мода и пакет установки

Репозиторий: `https://github.com/MortysCode/GTASA-COOP`. Стабильные выпуски публикуются через GitHub Actions при push нового тега `v*`.

1. Соберите и проверьте новую версию, загрузите исходники.
2. Отправьте тег соответствующей версии, например `v0.3.1.10`. Для ручной публикации откройте **Releases → Draft a new release**.
3. Прикрепите **отдельными файлами** содержимое подготовленной папки `SA-COOP-GitHub-release`:
   `sa-coop-update.json`, `SA-COOP-ВЕРСИЯ-update.zip`, `SA-COOP-Launcher-win-x64.zip`.
4. Опубликуйте обычный стабильный релиз, не Draft и не Prerelease.
5. Нажмите «Проверить обновления» в лаунчере. Он увидит этот выпуск.

ZIP мода и `sa-coop-update.json` всегда публикуются парой, сформированной упаковщиком.
Не меняйте ZIP после создания манифеста: иначе контрольная сумма справедливо не совпадёт.
Менять release notes и название релиза можно. Каждому следующему выпуску нужен новый номер версии.

Установочный пакет модов хранится отдельно в релизе `modpack-v1.0.0`: `sa-coop-install.json` и `SA-COOP-Modpack-1.0.0.zip`.
Он отмечен prerelease, чтобы не подменять последний стабильный релиз игрового мода.
Сборка пакета: `python tools/package_installation.py --game "D:/Grand Theft Auto - San Andreas" --version 1.0.0`.
Проверка: `dotnet run --project launcher/CoopLauncher.Tests -c Release -- --installation build/installation-release/sa-coop-install.json`.
Упаковщик требует Python 3.12+, исключает базовую GTA и личные файлы. При изменении набора используйте новый номер пакета и обновите `LauncherInfo.InstallationReleaseTag`.

## Сборка и будущие выпуски

Средства разработки: .NET SDK 8 и Python 3; для мода — llvm-mingw из `tools/get-toolchain.ps1`.

```powershell
python tools/build.py dist
dotnet run --project launcher/CoopLauncher.Tests -c Release
dotnet publish launcher/CoopLauncher/CoopLauncher.csproj -c Release -r win-x64 --self-contained true -p:RuntimeFrameworkVersion=8.0.30 -o build/launcher/win-x64
python tools/package_launcher_release.py --tag v0.3.1.10
```

Последняя команда кладёт готовые release assets в `build/github-release`.
Версию мода и протокол читает из `src/common/config/version/Version.h`.
При смене версии поправьте тег в команде. Упаковщик отклоняет тег, не совпадающий с бинарной сборкой.

В `.github/workflows/release.yml` есть сборка и публикация на GitHub Actions при push тега `v*`.
Она заработает после загрузки исходников и workflow в репозиторий. В GitHub используются
стандартные краткоживущие `GITHUB_TOKEN`/`GH_TOKEN` с правом записи Contents; постоянный ключ
в лаунчер не встраивается. Первую публикацию можно сделать вручную по инструкции выше.

Сам лаунчер автоматически себя пока не заменяет: новая версия его EXE распространяется
отдельным архивом в Releases. Манифест может указать минимальную требуемую версию лаунчера.

## Проверки

Консольные тесты создают только временные поддельные папки GTA. Проверяются установка,
сохранность настроек/сейвов/профилей, резервная копия, сбой после каждого из трёх файлов,
откат первой установки, заблокированный файл, запущенная игра, повреждённые контрольные суммы,
ZIP traversal, повторные имена, подмена подготовленного файла, восстановление после прерывания,
повреждённая резервная копия, GitHub metadata/download и отсутствие релиза.
Реальный сетевой тест публикации требует существующего публичного релиза указанного формата.
